# Native Spec Pipeline Integration — Let swagger-php Scan

## Why Not Hybrid Mode

The `Builder::Mode::HYBRID` in swagger-php doesn't fit NelmioApiDocBundle because:

1. **`HybridBridge` skips annotations without reflectors** — Nelmio creates many annotations programmatically (via `Util::createContext()`) that have no real `\Reflector`. The bridge drops these.

2. **`HybridBridge` doesn't transfer attachables** — `#[Model]` (Nelmio's core mechanism) uses the `Attachable` pattern. The bridge has no conversion for these.

3. **Nelmio's processors need fully-populated Analysis** — they rely on schemas that were dynamically generated by `ModelRegistry`, not source-scanned.

4. **The hybrid processor pipeline is stripped** — only `MergeJsonContent`/`MergeXmlContent` run. Nelmio's processors can't be injected at the right lifecycle point.

## The Alternative: Participate Natively in swagger-php's Spec Pipeline

Instead of maintaining a parallel scanning/describing system, NelmioApiDocBundle becomes **a set of augmenters + one `AttributeTranslatorInterface`** plugged into swagger-php's standard pipeline:

```
swagger-php Assembler (scans controller + model files)
    ↓
AttributeTranslatorInterface (Nelmio: synthesize operations for bare routes)
    ↓
Specification (operations w/ reflectors, schemas w/ reflectors)
    ↓
Augmenter Pipeline:
    ├─ [Group::Resolve]
    │   ├─ swagger-php: Inheritance, Names, Enums, Shortcuts, PathItems
    │   ├─ Nelmio: RouteBindingAugmenter        → fills path/method from router
    │   ├─ Nelmio: OperationFactoryAugmenter    → creates bare operations for undocumented routes
    │   ├─ Nelmio: ModelResolutionAugmenter     → resolves #[Model] → schema refs
    │   ├─ Nelmio: SerializationGroupAugmenter  → filters properties by serialization group
    │   ├─ Nelmio: PropertyInfoAugmenter        → fills types from PropertyInfo/TypeInfo
    │   ├─ Nelmio: MapQueryStringAugmenter      → expands to query parameters
    │   ├─ Nelmio: MapRequestPayloadAugmenter   → creates request body schemas
    │   ├─ Nelmio: OperationIdAugmenter         → sets operationId from route name
    │   ├─ swagger-php: Types, Refs, PathFilter, Cleanup
    │   └─ ...
    ├─ [Group::Reduce]
    │   └─ swagger-php: Cleanup
    └─ [Group::Augment]
        ├─ swagger-php: MediaTypes, Docblocks, OperationIds, Tags
        └─ Nelmio: SecurityAugmenter           → applies #[IsGranted] security schemes
    ↓
Compiler (3.0 / 3.1 / 3.2)
    ↓
array output
```

## What swagger-php's Scanner Already Handles

These currently live in Nelmio's describers but become redundant when swagger-php scans:

| Nelmio component | swagger-php equivalent |
|---|---|
| `OpenApiPhpDescriber` — reads `#[OA\*]` from controllers | `Assembler::collectFromClass()` |
| `OpenApiAnnotationsReader` — reads `#[OA\Schema]`/`#[OA\Property]` from models | `Assembler::collectFromClass()` + `membersOf()` |
| `Util::getPath()` / `getOperation()` / `getSchema()` | Flat `$spec->operations[]` / `$spec->schemas[]` |
| `Util::merge()` deep-merge | `AttributeFactory::resolveNesting()` / `resolveHierarchy()` |
| `Util::createContext()` | `$attribute->setReflector()` (reflector stored directly) |
| `SetsContextTrait` | Not needed — no global context |

## Key Mechanism: Reflectors Bridge to Symfony's Router

Since spec attributes carry the `\Reflector`, an augmenter can look up routes:

```php
foreach ($specification->operations as $operation) {
    $reflector = $operation->getReflector();
    // \ReflectionMethod → controller::action → Symfony Router → Route path
    $route = $this->router->getRouteForController($reflector);
    $operation->path ??= $route->getPath();
    $operation->method ??= $route->getMethods()[0] ?? 'get';
}
```

No synthetic `Context` objects needed.

## Component Mapping

### 1. AttributeTranslatorInterface — Route-based Operation Synthesis

Handles the case where a controller method has a Symfony route but no OA attribute.

```php
namespace Nelmio\ApiDocBundle\Spec;

use OpenApi\AttributeInterface;
use OpenApi\AttributeTranslatorInterface;
use OpenApi\Spec as OA;
use Symfony\Component\Routing\RouterInterface;

/**
 * Synthesizes an OA\Operation for controller methods that have a Symfony route
 * but no explicit OpenAPI attribute.
 *
 * This ensures all routed endpoints appear in the spec even without manual annotation.
 */
class SymfonyRouteTranslator implements AttributeTranslatorInterface
{
    public function __construct(
        private readonly RouterInterface $router,
        private readonly array $routeControllerMap,
    ) {
    }

    public function getAttributes(
        \ReflectionClass|\ReflectionMethod|\ReflectionProperty|\ReflectionParameter|\ReflectionClassConstant $reflector,
    ): array {
        return [];
    }

    public function translate(array $attributes): array
    {
        // Only applies to methods
        if ($attributes === []) {
            return $attributes;
        }

        $first = $attributes[0] ?? null;
        if (!$first instanceof AttributeInterface) {
            return $attributes;
        }

        $reflector = $first->getReflector();
        if (!$reflector instanceof \ReflectionMethod) {
            return $attributes;
        }

        // Check if already has an Operation
        foreach ($attributes as $attr) {
            if ($attr instanceof OA\Operation) {
                return $attributes;
            }
        }

        // Check if this method is a routed controller action
        $controllerKey = $reflector->getDeclaringClass()->getName() . '::' . $reflector->getName();
        if (!isset($this->routeControllerMap[$controllerKey])) {
            return $attributes;
        }

        // Synthesize a bare Operation — path/method filled later by RouteBindingAugmenter
        $op = new OA\Operation();
        $op->setReflector($reflector);
        $attributes[] = $op;

        return $attributes;
    }
}
```

### 2. RouteBindingAugmenter — Fills Path and Method from Symfony Router

```php
namespace Nelmio\ApiDocBundle\Augmenter;

use OpenApi\Augmenter\Group;
use OpenApi\Spec as OA;
use OpenApi\Specification;
use OpenApi\Utils\PipeInterface;
use Symfony\Component\Routing\RouterInterface;

/**
 * Fills operation path and method from Symfony's router by matching the
 * operation's reflector to a known route.
 *
 * @implements PipeInterface<Specification>
 */
final class RouteBindingAugmenter implements PipeInterface
{
    /** @var array<string, array{path: string, methods: list<string>, name: string}> */
    private array $routeMap;

    public function __construct(RouterInterface $router)
    {
        $this->routeMap = $this->buildRouteMap($router);
    }

    public function group(): string|\BackedEnum
    {
        return Group::Resolve;
    }

    public function __invoke(mixed $payload): mixed
    {
        foreach ($payload->operations as $operation) {
            $reflector = $operation->getReflector();
            if (!$reflector instanceof \ReflectionMethod) {
                continue;
            }

            $key = $reflector->getDeclaringClass()->getName() . '::' . $reflector->getName();
            if (!isset($this->routeMap[$key])) {
                continue;
            }

            $route = $this->routeMap[$key];
            $operation->path ??= $route['path'];
            $operation->method ??= strtolower($route['methods'][0] ?? 'get');
        }

        return null;
    }

    private function buildRouteMap(RouterInterface $router): array
    {
        $map = [];
        foreach ($router->getRouteCollection() as $name => $route) {
            $controller = $route->getDefault('_controller');
            if ($controller === null) {
                continue;
            }
            // Normalize "App\Controller\Foo::bar" format
            $map[$controller] = [
                'path' => $route->getPath(),
                'methods' => $route->getMethods() ?: ['GET'],
                'name' => $name,
            ];
        }
        return $map;
    }
}
```

### 3. ModelResolutionAugmenter — Resolves `#[Model]` Attachables

Replaces the current `ModelRegister` + `ModelRegistry` flow.

```php
namespace Nelmio\ApiDocBundle\Augmenter;

use Nelmio\ApiDocBundle\Spec\ModelAttachable;
use OpenApi\Augmenter\Group;
use OpenApi\Spec as OA;
use OpenApi\Specification;
use OpenApi\Utils\PipeInterface;

/**
 * Resolves #[Model] attachables into schema $refs and generates the component schemas.
 *
 * Walks all schemas looking for ModelAttachable, then uses the ModelRegistry
 * to describe the referenced type (with serialization groups, options, etc.)
 * and adds the resulting schema to the specification.
 *
 * @implements PipeInterface<Specification>
 */
final class ModelResolutionAugmenter implements PipeInterface
{
    public function __construct(
        private readonly ModelDescriberRegistry $registry,
    ) {
    }

    public function group(): string|\BackedEnum
    {
        return Group::Resolve;
    }

    public function __invoke(mixed $payload): mixed
    {
        // Collect all #[Model] attachables from the specification
        $modelsToResolve = [];

        // Walk operations → responses/requestBody → mediaType → schema
        foreach ($payload->operations as $operation) {
            $this->collectModels($operation, $modelsToResolve);
        }

        // Walk top-level schemas
        foreach ($payload->schemas as $schema) {
            $this->collectModelsFromSchema($schema, $modelsToResolve);
        }

        // Resolve each model: describe it, add schema to specification, replace ref
        foreach ($modelsToResolve as $resolution) {
            $schemaName = $this->registry->describe(
                $resolution['model']->type,
                $resolution['model']->groups,
                $resolution['model']->options,
            );

            // Ensure schema exists in specification
            if (!$this->hasSchema($payload, $schemaName)) {
                $payload->schemas[] = $this->registry->getSchema($schemaName);
            }

            // Replace the ref on the parent schema
            $resolution['schema']->ref = '#/components/schemas/' . $schemaName;
        }

        return null;
    }

    private function collectModels(OA\Operation $operation, array &$models): void
    {
        foreach ($operation->responses ?? [] as $response) {
            foreach ($response->content ?? [] as $mediaType) {
                if ($mediaType->schema instanceof OA\Schema) {
                    $this->collectModelsFromSchema($mediaType->schema, $models);
                }
            }
        }

        if ($operation->requestBody instanceof OA\RequestBody) {
            foreach ($operation->requestBody->content ?? [] as $mediaType) {
                if ($mediaType->schema instanceof OA\Schema) {
                    $this->collectModelsFromSchema($mediaType->schema, $models);
                }
            }
        }
    }

    private function collectModelsFromSchema(OA\Schema $schema, array &$models): void
    {
        foreach ($schema->attachables ?? [] as $attachable) {
            if ($attachable instanceof ModelAttachable) {
                $models[] = ['schema' => $schema, 'model' => $attachable];
            }
        }

        foreach ($schema->properties ?? [] as $prop) {
            if ($prop->schema instanceof OA\Schema) {
                $this->collectModelsFromSchema($prop->schema, $models);
            }
        }

        foreach ($schema->allOf ?? [] as $child) {
            $this->collectModelsFromSchema($child, $models);
        }
    }

    private function hasSchema(Specification $spec, string $name): bool
    {
        foreach ($spec->schemas as $schema) {
            if ($schema->schema === $name) {
                return true;
            }
        }
        return false;
    }
}
```

### 4. MapQueryStringAugmenter

```php
namespace Nelmio\ApiDocBundle\Augmenter;

use Nelmio\ApiDocBundle\Spec\MapQueryStringAttachable;
use OpenApi\Augmenter\Group;
use OpenApi\Spec as OA;
use OpenApi\Specification;
use OpenApi\Utils\PipeInterface;

/**
 * Expands MapQueryString-annotated controller arguments into individual query parameters.
 *
 * Reads MapQueryStringAttachable placed on operations during translation,
 * finds the referenced schema, and creates one Parameter per property.
 *
 * @implements PipeInterface<Specification>
 */
final class MapQueryStringAugmenter implements PipeInterface
{
    public function group(): string|\BackedEnum
    {
        return Group::Resolve;
    }

    public function __invoke(mixed $payload): mixed
    {
        foreach ($payload->operations as $operation) {
            $models = [];
            foreach ($operation->attachables ?? [] as $attachable) {
                if ($attachable instanceof MapQueryStringAttachable) {
                    $models[] = $attachable;
                }
            }

            foreach ($models as $model) {
                $this->expandToParameters($payload, $operation, $model);
            }
        }

        return null;
    }

    private function expandToParameters(
        Specification $spec,
        OA\Operation $operation,
        MapQueryStringAttachable $model,
    ): void {
        $schema = $this->findSchema($spec, $model->schemaName);
        if ($schema === null || $schema->properties === null) {
            return;
        }

        $operation->parameters ??= [];

        foreach ($schema->properties as $property) {
            $name = $property->property;
            if ($property->schema?->type === 'array') {
                $name .= '[]';
            }

            $required = $model->isOptional
                ? false
                : in_array($property->property, $schema->required ?? [], true);

            $operation->parameters[] = new OA\Parameter(
                name: $name,
                in: OA\ParameterIn::Query->value,
                description: $property->schema?->description,
                required: $required,
                deprecated: $property->schema?->deprecated,
                schema: $property->schema,
            );
        }
    }

    private function findSchema(Specification $spec, string $name): ?OA\Schema
    {
        foreach ($spec->schemas as $schema) {
            if ($schema->schema === $name) {
                return $schema;
            }
        }
        return null;
    }
}
```

### 5. OperationIdAugmenter — Sets operationId from Route Name

```php
namespace Nelmio\ApiDocBundle\Augmenter;

use OpenApi\Augmenter\Group;
use OpenApi\Spec as OA;
use OpenApi\Specification;
use OpenApi\Utils\PipeInterface;
use Symfony\Component\Routing\RouterInterface;

/**
 * Sets operationId from the Symfony route name.
 *
 * Replaces swagger-php's default OperationIds augmenter with
 * route-name-based IDs that are stable across code refactoring.
 *
 * @implements PipeInterface<Specification>
 */
final class OperationIdAugmenter implements PipeInterface
{
    private array $routeMap;

    public function __construct(RouterInterface $router)
    {
        $this->routeMap = [];
        foreach ($router->getRouteCollection() as $name => $route) {
            $controller = $route->getDefault('_controller');
            if ($controller !== null) {
                $this->routeMap[$controller] = $name;
            }
        }
    }

    public function group(): string|\BackedEnum
    {
        return Group::Augment;
    }

    public function __invoke(mixed $payload): mixed
    {
        foreach ($payload->operations as $operation) {
            if ($operation->operationId !== null) {
                continue;
            }

            $reflector = $operation->getReflector();
            if (!$reflector instanceof \ReflectionMethod) {
                continue;
            }

            $key = $reflector->getDeclaringClass()->getName() . '::' . $reflector->getName();
            if (isset($this->routeMap[$key])) {
                $operation->operationId = $this->routeMap[$key];
            }
        }

        return null;
    }
}
```

### 6. SecurityAugmenter — Applies `#[IsGranted]` Security Schemes

```php
namespace Nelmio\ApiDocBundle\Augmenter;

use OpenApi\Augmenter\Group;
use OpenApi\Spec as OA;
use OpenApi\Specification;
use OpenApi\Utils\PipeInterface;

/**
 * Reads Symfony #[IsGranted] attributes from operation reflectors
 * and generates security requirements.
 *
 * @implements PipeInterface<Specification>
 */
final class SecurityAugmenter implements PipeInterface
{
    public function group(): string|\BackedEnum
    {
        return Group::Augment;
    }

    public function __invoke(mixed $payload): mixed
    {
        foreach ($payload->operations as $operation) {
            if ($operation->security !== null) {
                continue;
            }

            $reflector = $operation->getReflector();
            if (!$reflector instanceof \ReflectionMethod) {
                continue;
            }

            $security = $this->extractSecurity($reflector);
            if ($security !== []) {
                $operation->security = $security;
            }
        }

        return null;
    }

    /** @return list<OA\Security\Requirement> */
    private function extractSecurity(\ReflectionMethod $method): array
    {
        $requirements = [];

        // Check method-level and class-level #[IsGranted]
        $attrs = $method->getAttributes('Symfony\Component\Security\Http\Attribute\IsGranted');
        if ($attrs === []) {
            $attrs = $method->getDeclaringClass()->getAttributes(
                'Symfony\Component\Security\Http\Attribute\IsGranted'
            );
        }

        foreach ($attrs as $attr) {
            $instance = $attr->newInstance();
            $requirements[] = new OA\Security\Requirement(
                name: 'default',
                scopes: [$instance->attribute],
            );
        }

        return $requirements;
    }
}
```

## Integration Point: Builder Configuration

NelmioApiDocBundle's `ApiDocGenerator` would be replaced by a thin wrapper around swagger-php's `Builder`:

```php
namespace Nelmio\ApiDocBundle;

use OpenApi\Builder;
use OpenApi\Builder\Mode;
use OpenApi\Builder\Result;
use OpenApi\Utils\Pipeline;

final class ApiDocGenerator
{
    public function __construct(
        private readonly Builder $builder,
        private readonly iterable $augmenters,
        private readonly SymfonyRouteTranslator $routeTranslator,
        private readonly array $sources,
    ) {
    }

    public function generate(): array
    {
        foreach ($this->sources as $source) {
            $this->builder->addSource($source);
        }

        $this->builder->setMode(Mode::SPEC);

        // Register the route translator for operation synthesis
        $this->builder->withAttributeFactory(function ($factory) {
            $factory->getTranslators()->add($this->routeTranslator);
        });

        // Register Nelmio augmenters into the pipeline
        $this->builder->withAugmenters(function (Pipeline $pipeline) {
            foreach ($this->augmenters as $augmenter) {
                $pipeline->add($augmenter);
            }

            // Disable swagger-php's OperationIds — Nelmio provides its own
            $pipeline->get(\OpenApi\Augmenter\OperationIds::class)?->setEnabled(false);
        });

        $result = $this->builder->build();

        return $result->toArray();
    }
}
```

## Required swagger-php Changes

### Widen `Builder::addSource()` to Accept Reflectors

Currently `addSource(string|iterable $source)` treats all inputs as file paths (or iterables of paths) that go through `SourceScanner` → `TokenScanner::scanFile()` → `\ReflectionClass` → `Assembler::collect()`. The reflection step is an internal implementation detail buried inside the file loop.

Widen the definition of "source" so that reflectors are first-class inputs alongside paths:

```php
// Signature becomes:
public function addSource(string|\ReflectionClass|iterable $source): static

// In doBuildSpec(), partition sources into files vs reflectors:
$files = [];
$reflectors = [];

foreach ($this->sources as $source) {
    if ($source instanceof \ReflectionClass) {
        $reflectors[] = $source;
    } elseif (is_string($source)) {
        $files[] = $source;
    } elseif (is_iterable($source)) {
        foreach ($source as $item) {
            if ($item instanceof \ReflectionClass) {
                $reflectors[] = $item;
            } else {
                $files[] = $item;
            }
        }
    }
}

// File path → existing TokenScanner flow
foreach ($resolvedFiles as $file) {
    foreach (array_keys($tokenScanner->scanFile($file)) as $class) {
        $assembler->collect(new \ReflectionClass($class));
    }
}

// Reflectors → direct collect (no file scanning)
foreach ($reflectors as $reflector) {
    $assembler->collect($reflector);
}
```

This keeps the file-scanning path as the default/documented way for standalone swagger-php usage, but treats reflection as an equal entry point for framework integrations that already know their class graph (Symfony's router, Laravel's route registrar, etc.).

**Usage from NelmioApiDocBundle:**
```php
$builder = new Builder();
$builder->setMode(Mode::SPEC);

// Feed controller classes discovered from Symfony's router
foreach ($routeCollection as $route) {
    $class = $controllerReflector->getReflectionClass($route);
    if ($class !== null) {
        $builder->addSource($class);
    }
}

// Feed model classes explicitly (or let ModelResolutionAugmenter discover them)
foreach ($knownModelClasses as $class) {
    $builder->addSource(new \ReflectionClass($class));
}

$result = $builder->build();
```

**Why this is better than a separate `addReflector()` method:**
- "Source" is the right abstraction — it's what you want documented. Whether it's a file or a class is an implementation detail.
- Avoids API surface growth — one method, one concept.
- Iterables naturally mix both: `$builder->addSource(['/path/to/models/', $controllerReflection])`.
- The `SourceScanner` already has the concept of skipping — it just needs to not choke on non-string items.

### Other Changes

| Change | Why |
|---|---|
| `AttributeTranslatorInterface::translate()` receives reflector context | Translator needs to know which method it's synthesizing for — **already works**: attributes carry their reflector from `getAttributes()` call |
| Pipeline ordering within a group is insertion-order-stable | Nelmio augmenters must run before `Refs`/`Types` for the schemas they create to be resolved |
| `Pipeline::insertBefore(class)` | Position Nelmio augmenters precisely relative to built-in ones |
| `Assembler::collect()` is public (it already is) | Nelmio can feed additional reflectors post-scan if needed |

## Augmenter Ordering Detail

Within `Group::Resolve`, order matters:

```
1. Inheritance (swagger-php)       — expands PHP class hierarchy
2. Names (swagger-php)             — infers schema names from class
3. RouteBindingAugmenter (Nelmio)  — fills operation paths from router
4. ModelResolutionAugmenter (Nelmio) — resolves #[Model], creates schemas
5. SerializationGroupAugmenter     — filters schema properties
6. PropertyInfoAugmenter           — fills type info on described schemas
7. MapQueryStringAugmenter         — expands to parameters
8. MapRequestPayloadAugmenter      — creates request bodies
9. Enums, Shortcuts (swagger-php)  — resolve shorthands
10. Types (swagger-php)            — infers types from reflectors
11. Refs (swagger-php)             — resolves FQCN → JSON Reference
12. PathFilter, Cleanup (swagger-php)
```

This is achievable via `Pipeline::insert($augmenter, before: Types::class)` or explicit positional registration.

## Migration Path

### Phase 1: Parallel augmenter development

- Implement augmenters alongside existing code
- Both paths produce output; validate equivalence with tests
- Keep classic as default, spec as opt-in config flag

### Phase 2: Spec becomes default

- Remove describer/processor architecture
- `Util.php` removed
- `nelmio_api_doc.swagger.processor` tag deprecated → `nelmio_api_doc.augmenter` tag
- Requires swagger-php ^6.x

### Phase 3: Cleanup

- Remove classic code paths
- Simplify DI configuration
- Document `PipeInterface` for user-defined extensions
- Requires swagger-php ^7.x (spec is default there)
